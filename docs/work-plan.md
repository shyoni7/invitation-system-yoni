# מערכת הזמנות לאירועים: אפיון ותכנית עבודה

## רקע

הרפו `shyoni7/invitation-system-yoni` ריק (README בלבד). בונים מאפס מערכת לעסק אחד עם כמה עובדים, שיוצר דפי הזמנה דיגיטליים לאירועים (פרטיים ועסקיים), מפיץ קישור אחד לכל אירוע, והמוזמנים נרשמים בעצמם. העסק עוקב אחרי הנרשמים, שולח תזכורות, ומייצא נתונים.

## סיכום ההחלטות מהדיאלוג

| נושא | החלטה |
|---|---|
| משתמשים | עסק אחד, כמה עובדים, כל עובד עם משתמש וסיסמה, כולם רואים הכל |
| סוגי אירועים | פרטיים ועסקיים, אותו מנגנון |
| הפצה | קישור אחד לכל אירוע, מופץ ידנית (קבוצת וואטסאפ וכו'). אין שליחת הזמנות מהמערכת |
| צד המוזמן | דף הזמנה ציבורי + טופס הרשמה. המוזמן נרשם בעצמו |
| טופס הרשמה | שם מלא + טלפון (חובה), אימייל (רשות), מספר מגיעים + שמות כל המגיעים, הערות (כשרות, אלרגיות, הסעה) |
| דף ההזמנה כולל | תבנית מעוצבת עם מדיה (תמונה או GIF), פרטי אירוע, ניווט (Waze / Google Maps), הוספה ליומן, ספירה לאחור, קישור למתנה או תשלום (קישור חיצוני בלבד) |
| עיצוב | 10 תבניות מוכנות, כל אחת עם מקום להעלאת תמונה או GIF |
| תזכורת אוטומטית | אימייל לנרשמים שהשאירו אימייל. העסק קובע לכל אירוע מתי (ברירת מחדל: יום לפני) |
| תזכורת ידנית | בממשק הניהול, ליד כל נרשם: כפתור וואטסאפ (קישור wa.me, בלי API) וכפתור אימייל |
| ממשק ניהול | יצירה ועריכה של אירועים, רשימת נרשמים, סיכום מספרי, עריכה ומחיקה ידנית של נרשמים, ייצוא ל-Excel |
| סידור שולחנות | שלב מאוחר, אחרי שהכל עובד |
| שפות | עברית (RTL) + אנגלית |
| טכנולוגיה | Next.js + Supabase + Vercel |

## ארכיטקטורה

### מחסנית
- **Frontend + Backend:** Next.js 15 (App Router, TypeScript), Tailwind CSS
- **DB + Auth + Storage:** Supabase (Postgres, Supabase Auth למשתמשי העסק, Storage למדיה)
- **אימייל:** Resend (API פשוט, תבניות React Email, שכבה חינמית)
- **תזמון תזכורות:** Vercel Cron Job שרץ כל שעה, בודק אילו אירועים הגיעו לזמן התזכורת ושולח
- **i18n:** next-intl, שני locales: `he` (ברירת מחדל, RTL) ו-`en`
- **ייצוא Excel:** ספריית `xlsx` בצד השרת (Route Handler)
- **אירוח:** Vercel

### מבנה נתונים (Supabase)

```
events
  id, slug (ייחודי, לקישור הציבורי), title, event_type (private/business),
  description, date_time, venue_name, address, lat, lng,
  template_id, media_url, primary_color (אופציונלי),
  gift_link_url, reminder_offset_hours (ברירת מחדל 24),
  reminder_sent_at, rsvp_deadline, max_guests (אופציונלי),
  created_by, created_at, updated_at, is_active

registrations
  id, event_id, full_name, phone, email (nullable),
  guest_count, guest_names (jsonb array), notes,
  status (confirmed/cancelled), source (self/manual),
  created_at, updated_at

tables            (שלב מאוחר)
  id, event_id, name, capacity

registration_tables   (שלב מאוחר)
  registration_id, table_id
```

- מניעת כפילות: אינדקס ייחודי על `(event_id, phone)`. הרשמה חוזרת עם אותו טלפון מעדכנת את הקיימת.
- RLS: טבלת `events` ו-`registrations` פתוחות לקריאה וכתיבה רק למשתמשים מחוברים. הרשמה ציבורית נכנסת דרך Route Handler בצד השרת עם service role, כדי שהמוזמן לא יצטרך חשבון ולא יוכל לקרוא נתונים של אחרים.

### נתיבים (Routes)

```
/                         הפניה ל-/admin
/login                    כניסת עובדים
/admin                    רשימת אירועים
/admin/events/new         יצירת אירוע (טופס + בחירת תבנית + העלאת מדיה)
/admin/events/[id]        פרטי אירוע: סיכום מספרי, רשימת נרשמים, פעולות
/admin/events/[id]/edit   עריכת אירוע
/admin/events/[id]/tables שולחנות (שלב מאוחר)
/e/[slug]                 דף ההזמנה הציבורי (ללא התחברות)
(Server Action)           הרשמת מוזמן דרך פונקציית SQL מאובטחת inv_register
/e/[slug]/calendar.ics    GET, קובץ יומן
/api/events/[id]/export   GET, הורדת Excel
/api/cron/reminders       GET, מופעל ע"י Vercel Cron, שולח תזכורות
```

### תבניות הזמנה
- כל תבנית היא קומפוננטת React תחת `src/templates/` שמקבלת `event` ומציגה: מדיה, כותרת, תאריך ושעה, מיקום, ספירה לאחור, כפתורי ניווט ויומן, קישור מתנה, וטופס הרשמה.
- קובץ רישום `src/templates/index.ts` עם מזהה, שם, תמונת תצוגה מקדימה, ופלטת צבעים לכל תבנית.
- 10 תבניות בסגנונות שונים: קלאסי, מינימלי, פרחוני, מודרני כהה, זהב, ילדים, עסקי נקי, עסקי טכנולוגי, חגיגי, רומנטי.
- העלאת מדיה: תמונה (JPG/PNG/WebP) או GIF, הגבלת גודל 10MB, נשמר ב-Supabase Storage.

### כפתורי פעולה בדף ההזמנה
- **Waze:** `https://waze.com/ul?ll=LAT,LNG&navigate=yes`
- **Google Maps:** `https://www.google.com/maps/dir/?api=1&destination=LAT,LNG`
- **הוספה ליומן:** קובץ `.ics` שנוצר בשרת, וגם קישור Google Calendar
- **ספירה לאחור:** קומפוננטת client פשוטה

### תזכורות
- **אוטומטית:** Cron כל שעה. שאילתה: אירועים ש-`date_time - reminder_offset_hours <= now()` ו-`reminder_sent_at IS NULL`. לכל נרשם עם אימייל נשלח מייל תזכורת עם פרטי האירוע וקישור לדף. אחרי שליחה מסמנים `reminder_sent_at`.
- **ידנית בוואטסאפ:** `https://wa.me/972XXXXXXXXX?text=...` עם הודעה מוכנה מראש (שם המוזמן, אירוע, תאריך, קישור). נפתח בחלון חדש.
- **ידנית באימייל:** כפתור ששולח את אותו מייל תזכורת לנרשם בודד.

## תכנית עבודה

### שלב 0: תשתית (יום 1)
1. `create-next-app` עם TypeScript, Tailwind, App Router, ESLint
2. חיבור Supabase: פרויקט חדש, קבצי migration ב-`supabase/migrations/`, הגדרת RLS
3. `next-intl` עם קבצי תרגום `messages/he.json` ו-`messages/en.json`, RTL אוטומטי לפי locale
4. פריסה ראשונית ל-Vercel + משתני סביבה
5. README עם הוראות הרצה

### שלב 1: הרשאות וניהול אירועים (ימים 2-3)
1. דף login עם Supabase Auth (אימייל + סיסמה), middleware שמגן על `/admin/*`
2. רשימת אירועים ב-`/admin`
3. יצירה ועריכה של אירוע: טופס עם ולידציה (zod), בחירת תבנית מתוך גלריה, העלאת מדיה ל-Storage, בחירת כתובת עם קואורדינטות
4. יצירת slug ייחודי וקישור ציבורי להעתקה

### שלב 2: דף ההזמנה הציבורי והרשמה (ימים 4-6)
1. נתיב `/e/[slug]` שטוען את האירוע ומרנדר את התבנית שנבחרה
2. טופס הרשמה: שם, טלפון, אימייל, מספר מגיעים, שמות מגיעים (שדות דינמיים), הערות
3. `POST /api/register` עם ולידציה, מניעת כפילות לפי טלפון, הגנה בסיסית מספאם (rate limit לפי IP)
4. מסך תודה אחרי הרשמה
5. ניווט, הוספה ליומן, ספירה לאחור, קישור מתנה
6. 3 תבניות ראשונות (כדי לאמת את מבנה התבנית לפני שמכינים את כולן)

### שלב 3: ניהול נרשמים (ימים 7-8)
1. דף אירוע ב-admin: סיכום מספרי (מספר הרשמות, סה"כ מגיעים, כמה עם אימייל)
2. טבלת נרשמים עם חיפוש וסינון
3. הוספה ידנית, עריכה, מחיקה של נרשם
4. כפתור וואטסאפ וכפתור אימייל ליד כל נרשם
5. ייצוא ל-Excel

### שלב 4: תזכורות אוטומטיות (יום 9)
1. חיבור Resend, תבנית מייל תזכורת בעברית ואנגלית
2. שדה `reminder_offset_hours` בטופס האירוע
3. `GET /api/cron/reminders` + `vercel.json` עם cron כל שעה, מאובטח ב-`CRON_SECRET`
4. לוג שליחות בסיסי

### שלב 5: השלמת התבניות ושיפורי UX (ימים 10-12)
1. 7 התבניות הנותרות
2. תצוגה מקדימה של האירוע מתוך ה-admin
3. התאמה למובייל של כל התבניות (רוב המוזמנים יפתחו מהטלפון)
4. בדיקות קצה לקצה עם Playwright על זרימת ההרשמה

### שלב 6: סידור שולחנות (אחרי שהכל עובד)
1. טבלאות `tables` ו-`registration_tables`
2. מסך שולחנות: יצירת שולחנות עם קיבולת, גרירת נרשמים לשולחנות
3. ייצוא Excel כולל עמודת שולחן

## אימות

- **מקומי:** `npm run dev`, Supabase מקומי או פרויקט dev
- **זרימת מוזמן:** פתיחת `/e/[slug]`, מילוי טופס, בדיקה שהרשומה נכנסה ל-Supabase, בדיקה שהרשמה חוזרת עם אותו טלפון מעדכנת ולא מכפילה
- **זרימת עובד:** login, יצירת אירוע, העלאת מדיה, העתקת קישור, צפייה בנרשמים, ייצוא Excel, לחיצה על כפתור וואטסאפ ובדיקת ההודעה המוכנה
- **תזכורות:** הפעלה ידנית של `/api/cron/reminders` עם אירוע שזמנו הגיע, ובדיקה שהמייל נשלח ושהאירוע מסומן
- **RTL ושפות:** החלפה בין he ו-en ובדיקת כיווניות
- **מובייל:** Playwright עם emulation של iPhone על דף ההזמנה
- **פריסה:** Vercel Preview לכל PR, Production מ-main

## הנחות וסיכונים

- שליחת אימייל דרך Resend דורשת אימות דומיין של העסק. עד אז שולחים מדומיין בדיקה של Resend.
- קישור wa.me דורש שהטלפון יישמר בפורמט בינלאומי (972...). הטופס ינרמל אוטומטית מספר ישראלי.
- אין הגנה מלאה מפני הרשמות מזויפות בקישור ציבורי. rate limit + אפשרות למחיקה ידנית מספיקים לשלב זה. אם יהיה צורך, אפשר להוסיף קוד אירוע או CAPTCHA.
